## [Unreleased]

### Added
- `README.fr.md` — a French translation of the root README, and the convention for the rest ([#169](https://github.com/axonops/axonops-containers/issues/169)). A translation sits next to its source as `<name>.fr.md` rather than in a `docs/fr/` tree, both files carry a language switcher, and a new `Docs Translations` workflow fails a PR that edits an in-scope English doc without touching its translation — without that gate the French copy rots silently, and a reader cannot tell a stale translation from a current one. `DEVELOPMENT.md` records the in-scope list, what stays English-only and why, and the rule that code blocks, variable names, YAML keys and CLI output are never translated. Remaining in-scope documents follow in per-component PRs; the CI list only enforces files that have actually been translated.
- The Cassandra container healthcheck now also verifies the AxonOps agent, so a node whose `axon-agent` has died is no longer reported as healthy while silently missing from AxonOps ([#168](https://github.com/axonops/axonops-containers/issues/168)). A dead agent is reported in the healthcheck output but does not fail the check by default — Cassandra is still serving CQL, and failing it can make an orchestrator restart or drain a working node. `HEALTHCHECK_REQUIRE_AGENT=true` opts in to treating it as a failure. The agent is found by walking `/proc`, so nothing new is installed in the image.
- `k8ssandra/4.0` and `k8ssandra/4.1` use `healthcheck.sh` instead of an inline `curl` of the Management API liveness endpoint, so all three Cassandra versions have the same healthcheck behaviour.
- `docker-compose/03-secure-3-rack-cluster/` — a three-node, three-rack Cassandra cluster with `PasswordAuthenticator`, `CassandraAuthorizer`, remote JMX and static addressing on a fixed `10.17.64.0/24` subnet, monitored by a self-hosted AxonOps platform. It is a port of the widely-shared [crystalloide/cassandra-reaper](https://github.com/crystalloide/cassandra-reaper) Compose stack with Prometheus, Grafana, the three `cassandra_exporter` sidecars and Reaper replaced by AxonOps; the cluster topology, addressing, JVM flags, ulimits and security settings are kept as they were, and the README tables every deviation.
- `docker-compose/03-secure-3-rack-cluster/` keeps the original stack's storage layout: each node bind-mounts `./docker/cassandra0N` as its data directory and `./docker/cassandra0N-conf` as `/opt/cassandra/conf`, so a customer's configuration can be edited on the host and inspected after the container is gone. A new `setup.sh` creates the directories, seeds each configuration directory from the image actually being run, and sets ownership to uid 999; `docker compose up` fails without it, because Cassandra cannot start against an empty configuration directory. `./docker/` is gitignored.
- `axondb-search` writes `path.repo` and `plugins.security.disabled` to `opensearch.yml` by replacing the key rather than appending to it. Both were unconditional appends, which is invisible while `/etc/opensearch` is part of the image layer but not when it is a mounted volume: the setting is added again on every start and OpenSearch refuses to start on a duplicated key. Found by sweeping for the same pattern as the `cassandra-env.sh` append below; `plugins.security.ssl.http` already deleted before appending and was left alone. Applies to both 3.3.2 and 3.7.0.
- `axondb-search` deletes `plugins.security.ssl.http` with the entrypoint's own `_sed-in-place` helper instead of `sed -i`. `sed -i` replaces the file by renaming a temporary over it, which fails when the file is bind-mounted — the reason the helper exists. Both other edits in these entrypoints already used it.
- The Cassandra image entrypoint appends `. /usr/share/axonops/axonops-jvm.options` to `cassandra-env.sh` only when it is not already there. The append was unconditional, which is harmless while the file is part of the image layer but not when it is bind-mounted or on a volume: the line then survives the container and another identical one is added on every restart, growing without bound. Confirmed against the published image — one restart takes it from one line to two.
- All four `docker-compose/` examples use `ghcr.io/axonops/cassandra/cassandra:5.0.8-2.0.31-1.1.0`, the release carrying the `CASSANDRA_AUTHENTICATOR` entrypoint support and the agent-aware healthcheck. Example 03 previously pointed at a development image because no production build had the authentication fix; it no longer needs to. Every example now pins the full version tag rather than the floating `5.0.8`, with the digest `sha256:98fbf810…` in a comment above it, and the two READMEs that said the agent healthcheck "takes effect with the next Cassandra image release" now say it is in the pinned image. `versions.yaml` and `VERSIONS.md` record the release.
- The standalone Cassandra image entrypoint applies `CASSANDRA_AUTHENTICATOR`, `CASSANDRA_AUTHORIZER`, `CASSANDRA_ROLE_MANAGER` and `CASSANDRA_NATIVE_TRANSPORT_PORT` to `cassandra.yaml`. It already handled the addressing, snitch, cluster-name and token variables, but not these four, so a cluster asked for authentication started silently with `AllowAllAuthenticator` — the same documented-but-unwired failure the `OPENSEARCH_*` variables had. The list now matches the official Cassandra image's. Only affects images built with `INCLUDE_MGMT_API=false`; with the Management API present the upstream entrypoint applies these itself.

### Fixed
- `docker-compose/03-secure-3-rack-cluster/` pinned only `cassandra01` to the image that honours `CASSANDRA_AUTHENTICATOR`; `cassandra02` and `cassandra03` were left on the production tag, which ignores it. Two of the three nodes therefore joined the "secured" cluster with `AllowAllAuthenticator` and accepted unauthenticated connections on their own published CQL ports, while the README stated all three ran the newer image. All three now use it, and the README's verification step checks every node rather than the first.
- The Cassandra nodes in `docker-compose/` examples 01, 02 and 03 replaced the image's healthcheck with their own `nodetool statusbinary` test, which bypassed the agent check added to `axonops-healthcheck.sh` — the exact failure that check exists to catch, a node serving CQL while its `axon-agent` is dead and the node has vanished from AxonOps. They now run the image's own script, and each README documents `HEALTHCHECK_REQUIRE_AGENT`.
- `docker-compose/00-axonops-platform/docker-compose.yaml` carried stale `Preferred (immutable)` digests for `axondb-timeseries` and `axondb-search` — neither matched the version tag beside it, or the digest in `VERSIONS.md` and the other examples. Following the file's own advice to deploy the digest form pulled a different image from the one the tag resolves to. Its section headers also named the previous Cassandra and OpenSearch versions.
- `docker-compose/01-cassandra-cluster/README.md` documented `AXONOPS_CASSANDRA_SSL` as defaulting to `true`. The default is `false`, as the same README's troubleshooting section explains it must be — anyone setting it from the table hit `Invalid or unsupported protocol version (22)` and a backend that would not start.
- `AXONOPS_ORG_NAME` had three different documented defaults across the self-hosted examples: `example` in the Compose files, `my-organization` in `env.example`, and one of each in the READMEs. All now say `example`. Example 02 is unchanged — it has no default, because a SaaS organisation name cannot be guessed.
- The root `README.md` listed three Compose stacks; there are four. Example 03 was missing.
- `docker-compose/03-secure-3-rack-cluster/` referred to "the eight `ipv4_address` entries" in the README and the Compose file. There are seven.
- `cassandra-publish-signed` and `k8ssandra-publish-signed` pushed tagged images *before* running their verification steps, so any post-push failure left published tags that were never verified and never signed. This happened on the Cassandra 1.0.0 run: 5.0.3 was pushed, failed its cqlai test, skipped signing, and sat in the registry unsigned. Both pipelines now push by digest only, run the test suite, sign the digest, and apply tags last with `docker buildx imagetools create` — asserting that every tag resolves to the digest that was signed. A failure at any stage now leaves nothing pullable by tag.
- `k8ssandra-publish-signed` re-ran the entire multi-arch build after signing purely to re-apply tags. That second build is gone; tagging copies the existing index instead.

### Fixed
- `k8ssandra-test-cqlai` verified query output by piping `cqlai` straight into `grep -q`. `grep -q` exits on the first match, SIGPIPEs `cqlai`, and under `pipefail` the step fails with exit 141 whenever the write loses the race — it took out a Cassandra 5.0.3 publish job. The output is now captured before matching.
- `fail-fast` disabled on the `cassandra-publish-signed` and `k8ssandra-publish-signed` build matrices. One version failing was cancelling every other version mid-publish, which can leave a release half-pushed with inconsistent floating tags.
- `docker-compose/01-cassandra-cluster/` connected to `axondb-timeseries` with `CQL_SSL=true` while the Cassandra native transport was plaintext, so `axon-server` never started: Cassandra logged `Invalid or unsupported protocol version (22)` (the first byte of a TLS ClientHello read as a CQL protocol version) and `axon-server` logged `tls: first record does not look like a TLS handshake`. The image only enables `client_encryption_options` when a keystore is mounted at `CASSANDRA_KEYSTORE_PATH` — `CASSANDRA_CLIENT_ENCRYPTION_ENABLED`, which the example passed, does nothing — so `CQL_SSL` now defaults to `false` and the two no-op variables are gone.
- `docker-compose/01-cassandra-cluster/` set `AXON_SERVER_URL` for `axon-dash`, which the dash accepts through its loose `AXON_SERVER_*` prefix mechanism and silently ignores, leaving `private_endpoints` at `http://127.0.0.1:8080` — itself — so it crash-looped with `findHost | no reachable endpoints`. Now uses `AXONSERVER_PRIVATE_ENDPOINTS`, the name its section-and-key mapping actually expects.
- `axondb-search` never applied `OPENSEARCH_DISCOVERY_TYPE`. The entrypoint printed it in the startup banner and the README documented it with a default of `single-node`, but nothing wrote `discovery.type` to `opensearch.yml` and the variable was never defaulted. With `network.host` at `0.0.0.0` OpenSearch runs its production bootstrap checks and refuses to start: `the default discovery settings are unsuitable for production use`. Both the 3.3.2 and 3.7.0 entrypoints now default the variable to `single-node` and write it to `opensearch.yml`.

Example 02's side-by-side comparison table, which duplicated the index, is replaced by the three differences that actually matter when running it — credentials, TLS, and where metrics are stored.

- `k8ssandra/README.md` referenced `examples/axon-cluster.yml` in eight places; no such file exists. Pointed at the real `examples/k8ssandra/cluster-axonops-ubi.yaml`.
- Root `README.md` and `cassandra/README.md` link to the Docker Compose examples.

### Added
- `docker-compose/02-saas-cassandra-cluster/`: a 3-node Apache Cassandra cluster whose agents report to AxonOps SaaS over outbound TLS, with no AxonOps platform running locally. Requires an organisation name and an agent key, both enforced by Compose at start-up, and runs in roughly half the RAM of example 01.
- `docker-compose/` directory of runnable Docker Compose examples built from this repository's images, with an index README documenting the shared conventions (version-tag pinning with digests in comments, all configuration through `.env`, development sizing by default). First example, `docker-compose/01-cassandra-cluster/`, deploys the self-hosted AxonOps stack (`axondb-timeseries`, `axondb-search`, `axon-server`, `axon-dash`) alongside a 3-node Apache Cassandra cluster, one rack per node, reporting to `axon-server` over the compose network. The monitored nodes default to `ghcr.io/axonops/cassandra/cassandra-dev` because the production repository `ghcr.io/axonops/cassandra/cassandra` has no published tags yet; the image is selectable with `CASSANDRA_IMAGE` in `.env`.
- `versions.yaml` and generated `VERSIONS.md` at the repository root: the current tag and SHA256 digest of every published image and Helm chart, in deployment order, with previous releases newest-first. Generated by the new `scripts/update-versions.sh`, which also refreshes digests from the registries (`--refresh`) and can gate CI on the Markdown being in step with the YAML (`--check`).
- "Image Pinning: Tags vs Checksums" section in `docker-compose/00-axonops-platform/README.md`, showing both reference forms for the compose stack and explaining why the digest is preferred, with per-reference guidance and commands for resolving a digest from a version tag.

### Added
- `INCLUDE_MGMT_API` build argument on `k8ssandra/5.0/Dockerfile` (default `true`). With `false` the build removes `/opt/management-api` and `/opt/cdc_agent`, strips the Management API java agent from `cassandra-env.sh`, starts Cassandra directly rather than through the Management API entrypoint, and healthchecks on the native transport. The default leaves the K8ssandra image unchanged.
- New standalone Apache Cassandra image, published from its own pipeline as `ghcr.io/axonops/cassandra/cassandra:{CASSANDRA}-{AGENT}-{BUILD}` (for example `5.0.8-2.0.31-1.0.0`) — the k8ssandra Dockerfile built with `INCLUDE_MGMT_API=false`. Covers Cassandra 5.0.1 through 5.0.8, multi-arch (amd64/arm64), cosign-signed, with floating `{CASSANDRA}-{AGENT}`, `{CASSANDRA}`, `5.0-latest` and `latest` tags. The agent component of a tag is always resolved to a concrete version, never the literal `latest` ([#157](https://github.com/axonops/axonops-containers/issues/157)).
- `CASSANDRA_*` environment variable handling in `k8ssandra/5.0/axonops-entrypoint.sh` for images without the Management API: seeds, listen/broadcast/rpc addresses, cluster name, num_tokens, endpoint snitch, dc and rack, plus the `/config` overlay. Mirrors what the upstream Management API entrypoint does, so the environment variable interface is the same for both images.
- Container healthcheck moved to `k8ssandra/5.0/healthcheck.sh`, which uses the Management API liveness endpoint when the API is present and `nodetool statusbinary` plus a CQL port check when it is not.
- Process supervision and automatic restart for the `axon-agent` sidecar process in the k8ssandra (`k8ssandra/{4.0,4.1,5.0}/axonops-entrypoint.sh`) and strimzi (`strimzi/files/axonops-wrapper.sh`) container images. If the agent exits it is now restarted automatically, with crash-loop protection (>5 restarts in 60s triggers a 30s backoff) and death/restart events logged to stdout and `/var/log/axonops/axon-agent.log`. Previously a dead agent was never detected or restarted for the life of the container ([#154](https://github.com/axonops/axonops-containers/issues/154)).
- Strimzi operator 0.51.0, 1.0.1 and 1.1.0 added to the build matrix across all four strimzi CI workflows (`strimzi-build-and-test`, `strimzi-development-build-and-test`, `strimzi-publish-signed`, `strimzi-development-publish-signed`), with pinned base-image digests and `VERSION_MATRIX` entries. Supported Kafka versions: 0.51.0 → 4.1.0/4.1.1/4.2.0; 1.0.1 → 4.1.0/4.1.1/4.1.2/4.2.0; 1.1.0 → 4.2.0/4.2.1/4.3.0.
- OpenSearch 3.7.0 support: new `axonops/axondb-search/opensearch/3.7.0/` Dockerfile directory.
- OpenSearch 3.7.0 added to the `axondb-search-build-and-test` and `axondb-search-development-publish-signed` CI matrix alongside 3.3.2.
- `opensearch_version` input (default `3.7.0`) added to `axondb-search-publish-signed` workflow to allow version-targeted production releases.
- Cassandra 5.0.7 added to `k8ssandra-build-and-test` secondary version matrix.
- Cassandra 5.0.8 support across k8ssandra and AxonDB TimeSeries CI workflows: build-and-test, nightly security scan, publish-signed, development-publish-signed, e2e-test, cloud-install-test, backups-publish-signed.
- New `axonops/axondb-timeseries/5.0.8/` Dockerfile directory for AxonDB TimeSeries images.
- New helper script `k8ssandra/scripts/set_latest_k8ssandra_version.sh` that reads the `K8SSANDRA_VERSIONS` GitHub Actions repository variable and sets `K8SSANDRA_VERSION` to the highest Cassandra semver found. Supports `--repo OWNER/REPO` and `--dry-run`; requires the `gh` CLI and `jq`.
